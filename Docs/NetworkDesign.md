# 网络同步设计与验证边界

## 范围

本项目是 UE 5.5、OnlineSubsystemNull、Listen Server 的双人局域网合作原型。
建房公布主机当前地图，不自动选择或切换到玩法地图；重开只重新加载当前关卡。
不包含账号服务、主机迁移、自研角色预测回滚或专用服务器部署。

## 谁决定状态，谁负责显示

| 对象 | 服务器负责 | 客户端获得什么 |
| --- | --- | --- |
| Character | CharacterMovement 校验和移动处理 | 引擎的移动同步、预测和校正 |
| CoopKey / KeySocket | 玩家重叠触发、归位、一次性登记 | 宝物完成状态、Actor 附着/位置；总进度见 GameState |
| PressurePlate | 不同玩家统计、目标条件、开关 | 开关状态和初始速度，本地播放压下/弹起 |
| CoopGate | 合并压力板状态与不同玩家集合 | 开关状态和初始速度，本地播放开关门 |
| MovingPlatform | 启停条件与固定轨道运动 | Actor 位置复制，默认更新频率上限 30 Hz |
| CoopGameState | 保存 GameMode 提交的目标结果 | 目标进度、目标总数、胜利状态的一份快照 |
| PlayerController / Presenter | 重开请求交 GameMode 校验 | 监听当前状态，补读晚到的胜利结果并显示本地 UI |

属性复制表达的是当前结果，不保证客户端逐次观察到所有中间变化。
客户端表现必须可以从当前状态恢复，不能依赖“曾收到过一次开门 RPC”。
不同 Actor 的更新不是跨对象原子事务，不能要求宝物、插槽和 GameState 在同一帧全部到达。

## 静止机关的网络休眠

门和压力板使用 `DORM_DormantAll`，兼容关卡摆放和运行时生成。
服务器改变复制属性之前调用 `FlushNetDormancy`，随后写入状态、更新本机表现并请求网络更新。
初始 JSON 速度也是复制属性，其赋值前同样刷新休眠。

这里的三个开关职责不同：

- 停止 Tick：不再逐帧计算本地运动。
- 降低 NetUpdateFrequency：降低常规复制更新频率目标，不承诺固定收包间隔。
- 网络休眠：减少未变化 Actor 的复制检查；不应以每帧唤醒抵消收益。

`ForceNetUpdate` 是调度请求，不是所有客户端已经收到状态的确认。
休眠变更必须回归初次加入、晚加入、反复开关和两端配置不同的场景。
压力板的占用变化事件和激活变化事件仍各自保留：人数变动即使没有改变开关，也可能改变合作门条件。

## 移动与碰撞边界

平台仍由服务器 Transporter 沿固定轨道运动，普通 Actor 位置复制不等于 CharacterMovement 的网络平滑。
平台不做轨道 Sweep，轨道避障由关卡布置保证；不能把 BlockAll 描述成自动避障或防挤压。
客户端站立、行走、跳上跳下、反向和停止必须在有画面的客户端补查。

门和压力板当前按收到的状态开始本地过渡，没有共同的服务器过渡起始时间。
门的碰撞跟随本机网格，两端过渡进度在弱网下可能暂时不同。
若测试证明影响通行，再补服务器起始时间和起始进度；不能只为了简历提前加入预测回滚。

## 会话、失败和重连

Session 负责发现房间；解析地址并 ClientTravel 才建立游戏连接。
菜单操作互斥，JoinSession 成功不立即等同于玩家已经进入游戏。
全局网络失败事件按 World/GameInstance/NetDriver 过滤，避免处理其他游戏实例的错误。
引擎也会向服务端报告单个远端客户端的超时/断开；此时主机仍正常监听，只记录该连接失败，不清除主机会话和房间广告。客户端丢失主机连接才进入有限重连或本地失败清理。

建房失败需回收本次新建的监听，不能误拆早已存在的主机连接。
重开请求先去重；若加载失败且旧 World 仍存活，需恢复该局重开所需的状态，再允许重试。
原地 `World::Listen` 不会自动将监听选项写入引擎 `LastURL`，而 `?Restart` 会重新读取该 URL。
因此合法的 Listen Server 重开请求需保留 `listen` 选项，否则新世界会退回单机；仍只重载当前关卡。
开发用故障注入与真实网络中断分开记录，故障注入只能证明对应错误处理分支。
测试中的首次建房失败和首次重开失败是开发注入，不代表所有平台服务故障或所有引擎加载错误都已复现。

自动重连使用已有地址与有限重试，主动退出会取消重连。
重连确认点是本地控制器进入 PlayingState；其他复制对象仍可能随后到达。
重连恢复服务器仍保存的共享状态，不恢复旧 Pawn、私人存档或主机已经丢失的状态。
当前不增加重连提示界面，错误信息仍以项目日志为主。

## 测试结果应如何解释

- 状态测试：分别检查服务器结果和客户端观察结果，不能只检查服务端变量。
- 压测：固定地图背景、玩家位置、相关性、时长与更新频率，一次只改变一个条件。
- 静止系列仅对比压力板保持唤醒/休眠；运动系列仅对比平台 100/30 Hz 更新频率上限，两类数量不交叉叠加。正式每组至少三次，单次短采样只检查工具链。
- CPU：观察服务器复制工作耗时，不把 Listen Server 的渲染时间当成网络成本。
- 发送量：当前采集服务器 NetDriver 引擎发送字节，含配置的包头开销、原地图和测试通信，不是单个机关的独占带宽。该计数不是网卡抓包或成功到达字节，不能用于宣称物理链路流量；B/s 表示字节每秒。
- 时延：模拟参数不等于实测 RTT；两端同时加发送延迟时会共同影响往返时间。
- 断包：测试进程临时设置 100% 入/出站丢包并缩短超时，等待引擎真实超时再恢复传输，不主动广播断线事件；不声称覆盖网卡、路由器和运营商的全部故障。
- 无画面测试可以检验状态和数值，不能证明视觉平滑、UI 排版和人工操作手感。
- 同机双进程不是双机局域网测试；开发版运行也不是打包交付验收。

自动场景会放置角色触发实际重叠，也会生成合成机关；它们不是完整人工通关录像。
胜利界面断言检查客户端状态和 Viewport 中的实例，不检查像素或按钮操作。
平台载人断言检查 CMC 基座、位移和偏移，不等于弱网下视觉平滑已经合格。
60 FPS 限制下的 100 Hz 参数不是实测发包频率；全零/缺失 CPU 计数必须注明，不能据此宣称没有成本。

每份报告记录代码版本、未提交状态、源码和配置指纹、命令、运行环境、断言以及日志路径。
失败、未运行和不适用必须分开，历史报告不得直接宣称当前版本通过。
运行入口、对照命令与报告口径统一维护在 [测试说明](../Tests/README.md)，这里不复制结果表。
