# 网络性能与验证报告

本报告汇总已记录构建的实测数据，分为当前 Dedicated Server 回归及历史参数对照。源数据保留报告 SHA-256、构建或模块指纹、断言和指标，各批次独立解释。

## 1. 实验设计

两类规模实验分别控制变量：

| 系列 | 压力档位 | 改变的变量 | 固定条件 | 主要指标 |
| --- | --- | --- | --- | --- |
| 静止机关 | 0 / 50 / 200 / 500 压力板 | 保持唤醒 / 网络休眠 | 新增平台为 0；两组频率上限均为 30 Hz | ServerReplicateActors 平均耗时、P95、休眠数量 |
| 运动平台 | 1 / 5 / 20 平台 | 100 / 30 Hz 频率上限 | 新增压力板为 0；平台持续往返 | 服务器发送 B/s、复制耗时 |

原关卡背景保持一致，合成对象强制网络相关。先预热再采样，不以启动/加载阶段代表稳定运行。100 Hz 是压力对照参数，常规平台实现使用 30 Hz 上限。

七种场景每档一次，共 **21 / 21**。收尾构建追加 Normal / Harsh 的 Flow，**2 / 2**。连接冒烟分别验证 DS 无本地玩家、两名真实远端玩家及独立回执。表中 Keys 对应这批历史构建的携带流程；当前源码和关卡采用触碰后自动归位，测试内容见 [测试说明](../Tests/README.md)。

正常、适度和重度网络模拟分别配置 PktLag / Variance / Loss 为 0 / 0 / 0%、100 ms / 20 ms / 2%、200 ms / 50 ms / 5%。Reconnect 在测试时仅阻断被测连接的服务器出站包，等待客户端真实超时，另一连接保留。

通过条件包含必需断言、三端成功 DONE、正常进程退出和致命日志检查。RideMotion 的通过表示动作及计量检查通过；校正次数、历史 Move 误差单独作为诊断数据解释。

## 3. DS 规模复核

Normal 网络；预热 5 秒，采样约 10 秒，每组一次。CPU 为每轮复制作用域均值；发送量为采样期间计数差除以实际秒数。

| 负载 | 参数 | 复制均值 ms | P95 ms | 发送 B/s | 平均休眠 Actor 数 |
| --- | --- | ---: | ---: | ---: | ---: |
| 500 静止压力板 | Baseline | 2.298 | 4.712 | 3,493 | 7 |
| 500 静止压力板 | Dormancy | 0.232 | 0.516 | 3,473 | 507 |
| 20 运动平台 | 100 Hz 上限 | 0.572 | 1.323 | 27,323 | 7 |

四例复核 **4 / 4 通过**。休眠数量和复制调用变化支持静止对象减少复制检查的解释；移动对象的频率对照显示发送量变化。单轮数据用于当前拓扑的工具链与参数复核，和下节三轮统计分开。

## 5. 指标口径

- CPU 取 `Exclusive/GameThread/ServerReplicateActors`，表示复制工作作用域；百分比只对应这一指标。
- B/s 取 `UNetDriver.OutTotalBytes` 的计数差，包含背景对象、测试通信与配置的包头开销。DS 包含两条远端连接。
- P95 采用 nearest-rank；三轮表中的 P95 是逐轮 P95 的中位数。
- 网络模拟参数不是测得的 RTT；100 / 30 Hz 是复制频率上限，不是固定发送间隔。
- NullRHI 用于状态与数值验证；视觉与交互体验通过可操作客户端观察。
- 同机进程共享 CPU。历史 0 对象控制组存在自然波动，数据按组顺序采集；小差异结合样本范围判断。

## 6. 复现入口

先构建项目并配置 `UE_EDITOR`，在根目录执行：

~~~powershell
# 当前 DS 全场景回归
.\Scripts\RunMultiplayerNetworkTests.ps1 -Scenario All -Profiles Normal,Moderate,Harsh -Repeat 1

# 静止与运动规模矩阵，分别改变单一参数
.\Scripts\RunMultiplayerNetworkTests.ps1 -Suite Scale -Matrix Static -StaticCounts 0,50,200,500 -Repeat 3
.\Scripts\RunMultiplayerNetworkTests.ps1 -Suite Scale -Matrix Moving -MovingCounts 1,5,20 -Repeat 3

# 重度弱网载人移动及自动时间线
.\Scripts\RunMultiplayerNetworkTests.ps1 -Scenario RideMotion -Profiles Harsh -Repeat 3
~~~

当前入口运行 DS 拓扑，产生新的运行批次。报告记录命令、环境、源码与配置指纹、各端断言及计量。详见 [测试说明](../Tests/README.md)。

## 7. 移动基座的时间戳诊断与频率取舍

诊断按同一 `MoveTimeStamp` 配对客户端 SavedMove 和服务器处理记录，分别记录角色世界位置、基座相对位置、平台位置、水平速度与基座状态。两端处理同一 Move 的时刻可以不同，因此这组配对用于解释一次移动的校正，不能当作同一物理时刻的快照。

2026-09-27 的 Harsh 单轮中，起跳 Move 两端平台 X 相差约 84.23 cm，角色水平速度均为 150 cm/s；离开基座后差异表现为世界位置误差。落回基座的 Move 中，角色世界 X 相同，但相对平台 X 相差约 75.06 cm。证据支持检查参考系转换时的平台状态，而非仅增加一次水平速度。

2026-09-29 进一步完成 30 / 60 Hz 上限的六轮交错对照：同一 UE 5.5.4 Editor-game 构建、Listen Server 与一个远端客户端、NullRHI、Harsh 模拟参数，每档三轮，每轮取四秒 Jump 阶段。正式平台保持 30 Hz。

| 频率上限 | 三轮校正次数 | 三轮最大可比较误差 / cm | 校正次数中位数 | 每轮最大误差的中位数 / cm |
| --- | --- | --- | ---: | ---: |
| 30 Hz | 11、19、12 | 79.26、65.17、67.16 | 12 | 67.16 |
| 60 Hz | 11、12、13 | 80.74、64.92、76.54 | 12 | 76.54 |

六轮动作断言通过，十二个进程正常退出；78 次校正均匹配到唯一双端记录。提高频率在本条件下没有显示稳定收益，因此保留 30 Hz。校正次数包含状态校正，和肉眼可见的回拉次数是不同指标；三轮最大误差的中位数也不是所有采样点的 P95。该历史定位实验与当前 DS 规模复核分别统计。

早期基座速度与惯性行为对照的脱敏记录见 [PlatformRide](../Tests/Evidence/2026-09-27/PlatformRide/)。上述六轮逐 Move 表与时间线保存在本机 `Saved/NetworkValidation/PlatformFrequency-20260929/`，记录目录与指标口径用于对应原始实验。
