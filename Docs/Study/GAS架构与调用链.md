# GAS 架构与调用链

先用 [面试主线](../INTERVIEW_GUIDE.md) 讲清职责与取舍，再沿本文追到函数；当前完成范围见 [测试记录](../../Tests/README.md)。不把预测激活、提交成功和最终命中当成同一次确认。

项目把联机战斗分为请求、激活、出手、效果结算和表现五段。客户端表达操作意图并预测自己的响应，服务器决定目标是否合法、是否产生投射物，以及最终伤害和治疗。整理的重点是让规则只有一个维护入口，而不是再增加一套战斗框架。

服务器拓扑、机关复制与连接管理见 [网络同步设计](../NetworkDesign.md)；各构建的实际验证范围见 [测试说明](../../Tests/README.md)。

## 职责与阅读顺序

当前目录与连接、机关、战斗边界见 [ARCHITECTURE](../ARCHITECTURE.md)。ASC 已从能力聚合头独立声明；服务器恢复结构位于 `Network/multiplayerCombatResumeState.h`，不是新组件或通用持久化框架。

以下文件均位于 `Source/multiplayer/`。头文件保留相关 GAS 类型声明，按职责拆实现不改变蓝图父类和资产引用。

| 阅读顺序 | 文件及入口 | 负责的事情 |
| --- | --- | --- |
| 1 | `Combat/multiplayerCombatCharacter.cpp` 的 `ActivateSkill`、`ActivateAimedSkill` | 接收玩家意图，选择 GAS 请求入口，协调角色生命周期 |
| 2 | `Combat/multiplayerCombatCharacterSkillStatus.cpp` 的 `CheckSkillAvailable`、`CheckSkillBusinessRequirements` | 查询真实能力资格、补充角色业务条件、把失败原因转换为提示 |
| 3 | `Combat/multiplayerCombatAbilitySystem.h/.cpp` | 将配置关系接入 GAS 阻断与取消机制，处理服务器拒绝和有限的预测清理 |
| 4 | `Combat/multiplayerCombatAbility.cpp` 的能力基类及具体技能 | 提交成本和冷却；组织起手、出手、收招与取消；定义对应 GE |
| 5 | `Combat/multiplayerCombatTargeting.cpp` | 查询方向、落点、目标、距离与遮挡，不提交战斗结果 |
| 6 | `Combat/multiplayerCombatProjectile.cpp`、`Combat/multiplayerCombatAttributes.cpp` | 权威弹体与命中、伤害计算、格挡、护盾和生命结算 |
| 7 | `Combat/multiplayerCombatPresentation.cpp` | 动画、GameplayCue、范围提示及事件驱动 HUD |

`CombatConfig` 保存基础参数、表现资源和能力标签关系；`Character::GetSkillRule` 在基础配置上应用技能等级，提供有效数值。配置不负责运行技能。成长与配装由 Progression 组件管理，倒地救援由 Coop 组件管理，冲刺由 Mobility 中的能力实现。

角色仍承担属性监听、生命状态和重连快照等协调职责；把同一角色的方法放进多个 `.cpp` 不等于组件隔离。执行投射物和范围伤害不再由角色入口包办，分别归投射物和范围能力。

面试先按三条线阅读，不必按文件逐个背诵：**请求与准入**（输入、Can、预测及服务器复核）；**提交与结算**（Commit、出手、GE 和属性）；**取消与恢复**（任务清理、实例复用和短时重连）。下面按这三条线展开。

## 从输入到 GAS 激活

Q、E、R、Shift 的按住预览只是本地查询和绘制，不扣费、不复制，也不创建预测键。松键或左键确认时才提交技能，右键取消预览。普通攻击直接请求对应技能。槽位先由 Progression 映射为技能，界面不维护另一份技能规则。

确认时先关闭预览并处理本次请求，最后通知界面。若先广播“预览关闭”再激活，监听者在通知中取消或切换后，旧请求仍可能继续启动。失败提示使用这次查询收集的原因，不为显示一句话重新查询资格。

```text
玩家输入
  → Character::ActivateSkill
  ├─ 普攻／防御／范围／冲刺
  │    → ActivateAimedSkill：把本次方向放入 GameplayEvent 的 TargetData
  │    → ASC::HandleGameplayEvent
  │    → TriggerAbilityFromGameplayEvent
  └─ 治疗等非定向入口
       → TryActivateAbilityByClass → TryActivateAbility
  → InternalTryActivateAbility
  → CanActivateAbility
  → CallActivateAbility：PreActivate → ActivateAbility
```

口述可记为 `尝试激活 → Can → Activate → Commit → End`。对应代码时，事件触发走 GAS 内部尝试入口，不一定显式调用公开的 `TryActivateAbility`，但仍经过正式资格检查。`CommitAbility` 和 `EndAbility` 由具体能力在合适阶段显式调用，不是 `ActivateAbility` 后引擎无条件自动完成的下一步。

敌人的服务器行为树任务直接调用 `TryActivateAbilityByClass` 请求自己的攻击能力；救援从角色入口请求专门的 ServerOnly 能力。它们共用 GAS 生命周期，但不需要伪造玩家的本地瞄准输入。

定向请求只上传方向意图。服务器验证事件类型、TargetData 结构和有限归一化旋转，再用服务器世界重建发射点、射程、地面与遮挡；不接受客户端提供伤害或命中名单。远端不能改走不带事件的普通激活 RPC 绕过该检查。

## 准入只有一条规则链

`CheckSkillAvailable` 是预览和提示的只读入口。它找到实际 AbilitySpec，优先查询现有能力实例的 `CanActivateAbility`，没有实例时使用能力定义；它自己不再复制成本、冷却和关系判断。

正式能力基类的 `CanActivateAbility` 先调用 `CheckSkillBusinessRequirements`，检查会话接纳、存活、倒地、救援、学习、能力是否授予、相同技能是否仍活动，以及冲刺的实际移动模式。然后调用 GAS 原生 `Super::CanActivateAbility`。

相同技能同时检查 Spec 活动计数和实例 `IsActive`。UE5.5 的 `PreActivate` 先将实例设为活动并广播拥有标签，最后才增加 Spec 计数；只检查 Spec，会允许标签回调在这个窗口嵌套激活同一实例。

GAS 调用的各检查有明确归属：

- `DoesAbilitySatisfyTagRequirements` 查询集中式关系，再保留原生能力标签约束。
- `CheckCost` 从有效规则读取能量需求；忽略消耗由原生激活和提交入口处理。
- `CheckCooldown` 保留原生冷却标签判断，只补充项目可读的失败标签。
- 治疗能力的 `CanActivateAbility` 额外要求存在合法受伤目标；目标不在通用基类里扫描。

本地查询通过不意味着服务器必然接受。延迟期间资源或状态可能变化，正式激活仍检查当时状态；服务器的真实拒绝原因只发给拥有者，不用客户端尚未纠正的预测余额重新推断原因。

对于所属客户端的 `LocalPredicted` 请求，GAS 在本地 Can 通过后创建预测键、发送激活 RPC，再执行本地 `ActivateAbility` 和提交。服务器用同一键独立检查、激活和提交，不等待客户端先扣费，也不接受客户端预检作为授权。激活确认、提交成功和最终命中是三个不同结果。

## 成本冷却与技能阶段

当前能量消耗共用一个 `UmultiplayerEnergyCostEffect`，数值仍由本次有效技能规则提供；技能不同不意味着需要四个内容相同的成本 GE 类。旧四个原生类型通过 CoreRedirects 迁移，不保留空继承类。伤害、治疗、防御、冷却等具有不同语义的效果没有合并成一个万能 GE。

```text
具体 Ability::ActivateAbility
  → 检查本技能的方向／落点等执行前提
  → CommitAbility
      → CommitCheck：再次检查此刻成本与冷却
      → CommitExecute：取得本次局部规则快照
          → 成本 GE → 能量变化
          → 检查本轮仍有效 → 冷却 GE
  → 起手任务 → 出手 → 收招任务 → EndAbility
```

激活资格检查与 `CommitCheck` 不是应该删除的重复：前者决定能否开始，后者防止开始后、付费前资源已经变化。项目的提交顺序是先扣资源再加冷却，避免冷却监听者用旧余额同步嵌套释放另一技能。

同一次 `CommitExecute` 使用一份局部有效规则固定成本和冷却，防止扣费事件同步改变等级后，冷却改读另一套数值。这不是跨网络的事务，也不是全技能数值快照；客户端和服务器仍各自计算并由权威结果纠正。独立调用原生成本或冷却提交接口时，分别读取当时有效规则。

技能之间保留不同的执行流程：

- 普攻固定本次方向，起手后由服务器通过 `Projectile::FireFromSkill` 创建弹体，命中再结算。
- 防御提交后施加限时 GE，能力本身可以结束，防御状态继续存在到效果结束。防御保持身体朝向，正面直接伤害完全格挡；侧后方、无方向范围伤害和周期伤害不因此免疫。
- 治疗在提交前确认目标存在，提交后重新查询合法目标，由服务器施加回血 GE。治疗不播放动作，特效落在实际目标上。
- 范围技能固定本次落点，起手结束调用 `AreaAbility::ResolveTargets`。取消起手不再产生范围伤害；出手后的同步伤害批次不因普通取消拆成半次，施法者死亡或眩晕则停止后续候选。已提交成本与冷却不退款，已结算伤害不倒退。
- 冲刺使用原生根运动任务，CMC 负责碰撞和位置纠正；敌人近战在起手前取黑板目标，出手时重新验证距离、方向与遮挡。

起手和收招由规则时钟驱动，不依赖是否配有 Montage。没有动画资源不能让攻击立即造成伤害；动画播放是表现，不是第二份攻击计时。敌人失去控制时先解绑状态通知再取消尚在进行的攻击，避免清除施法标签的回调重新启动旧 AI；已经发出的弹体保留自身生命周期。

敌人行为树的接近距离和真正攻击共用有效技能规则，不再维护可编辑的第二份 `AttackDistance`。近战取当前有效 Range；投射物取有效射程并受速度与存活时长限制。正式小兵的 160 和显式远程原型的 1100 属于各自配置，不能用测试夹具的数值冒充正式资产。

## 命中与属性结算

```text
服务器弹体扫掠／范围出手／近战出手
  → 实时验证存活、阵营、范围与遮挡
  → Character::ApplyCombatDamage
  → 创建伤害 GE Spec，写入基础伤害与来源上下文
  → DamageExecution：Max(0, 基础伤害 + 攻击加成 - Max(0, 护甲))
  → IncomingDamage
  → AttributeSet::PostGameplayEffectExecute
      → 固定本次正面格挡结果并清空 IncomingDamage
      → 护盾吸收 → 溢出扣生命 → 生命状态处理
  → 权威 Cue 与属性复制 → 各端表现和 HUD
```

攻击属性在创建伤害 GE Spec 时捕获，护甲按目标效果应用时的聚合值计算。普攻伤害 GE 在实际命中时创建，不能把它描述成发弹瞬间就锁定了所有属性。

范围查询分两步：先收集几何候选，再在每个目标即将结算前完整检查一次资格、范围、高度和视线。预览也使用相同几何与过滤规则，但不锁定未来命中名单。目标移动、死亡和遮挡变化必须在出手时复核；同一轮范围结算固定基础规则、半径和附加效果配置，不因前一个目标的回调临时改配置而变化。攻击加成仍在各伤害 Spec 创建时捕获，不是所有来源属性的批次快照。

属性通知是同步回调，可能再触发伤害、取消或死亡。清空 `IncomingDamage` 后才消费它，扣盾后重新检查资格并使用最新生命扣溢出，避免旧调用栈覆盖新状态。GameplayCue 只显示结果，不负责扣血或判断命中。

生命、能量和护盾的上限变化统一在 `PostAttributeChange` 钳制当前资源，持续效果到期或被移除也适用，不能只依赖瞬时效果的 `PostGameplayEffectExecute`。成长效果替换使用 GAS 原生聚合通知批次，只按最终上限处理，不因“先移旧效果”的中间上限误扣生命。

## 取消预测与实例复用

能力采用 `InstancedPerActor`，同一个能力实例会重复使用。准入检查拒绝已开始激活的实例；`ActivationRevision` 从具体能力开始执行时递增，用于区分同一对象不同轮执行，不覆盖整个原生 `PreActivate`。PredictionKey 区分预测请求，效果句柄标识本次施加的 GE，三者不互相替代。

取消处理遵循以下顺序：先认领结束、清空自己的句柄或提交已出手标记，再执行可能通知外部的清理。`Super::EndAbility` 结束本次 AbilityTask 和能力拥有的标签；具体能力清除自己的施法效果、根运动、目标引用和相关动作。停止 Montage 前确认它仍属于自己，旧结束回调不能停掉新技能。

每次扣费、授予标签、播放动画或广播之后，都可能发生同线程重入。版本和活动状态复核用于防止旧调用栈继续创建任务或结算；它们不是线程锁，也不证明业务是跨线程执行。

动画播放收口在现有 ASC 的 `PlayMontage`。UE5.5 先播放并同步通知 Started，后登记动画归属；项目在登记前检查请求是否仍有效，取消则停止本次动作，被新播放替换则旧栈退出。预测拒绝也核对播放请求，不能只按动画资产停止，否则旧请求可能误停下一轮同资产动作。这里保留 5.5 的复制和预测注册流程；升级引擎时需要复核该适配，不应把它描述成通用动画回滚系统。

玩家能力为 `LocalPredicted`，预测自己的成本、冷却、施法状态及可支持的动作；救援和敌人近战由服务器执行。GAS 预测键关联能够预测的效果，并在权威拒绝时撤销或校正；项目按同次预测键额外清理纯施法状态，不开放任意资源效果删除。

客户端不预测远端扣血、治疗结果或权威弹体命中。已播放的声音不能完整撤回，自定义 C++ 副作用不会因有 PredictionKey 就自动回滚。当前没有通用动作日志回滚、目标历史命中回溯或完整世界回滚。

## 状态限制与短时重连

能力互斥来自 Config 的标签关系：规定激活要求、阻断哪些能力和取消哪些能力，再叠加 GAS 原生规则。它借鉴 Lyra 的关系映射思路，不代表接入了 Lyra 的 Experience、AbilitySet 或输入架构。范围与治疗可按配置替换普通攻击，具体目标和命中条件仍由技能处理。

眩晕取消活动技能并暂停行动；禁锢阻止移动，但允许范围内的攻击。禁锢按独立 GE 计数，移除一份限制后只要另一份仍存在，就不能恢复移动。当前眩晕采用单份效果刷新时长，不宣称已经支持全部控制效果的独立多来源管理。

短时恢复流程为：

```text
断开前 Controller 保存状态 → GameMode 缓存带期限快照
客户端 GameInstance 有限重试 → 新 Controller 通过所属 RPC 交回票据
GameMode 验证票据并恢复新 Pawn → 设置战斗就绪 → 客户端完成连接
```

恢复血量、能量、护盾、位置、成长配装及支持的剩余冷却和效果，扣除离线时间；灼烧保留下一跳节奏并结算离线伤害。死亡或倒地超时不能因重连免费复活。半次施法、冲刺、救援和旧回调不恢复。

票据和快照仅覆盖仍运行的同一服务器、同一局及保留票据的客户端进程，缓存期限为 120 秒；不是账号登录、跨服务器恢复、服务器重启恢复或任意 GE 存档。

## 连续追问与简短回答

1. **为什么不在 Character 里判断完再激活？** Character 只补角色业务前提。真正能力的 `CanActivateAbility` 同时服务 HUD 查询与正式请求，成本、冷却和标签继续走 GAS，避免两套规则逐渐不一致。

2. **检查通过为什么还会失败？** 本地预览、服务器激活和正式提交发生在不同时刻；目标和资源可能变化。失败应返回实际拒绝原因，而不是把预览视为授权。

3. **为什么 Commit 还检查一次？** Can 决定能否开始，CommitCheck 决定现在能否付费。Commit 不重新调用完整 Can，因为能力已进入活动状态，本身可能让 Can 的条件不再成立。

4. **取消会返还能量和冷却吗？** 预览取消不消费。技能提交后取消不退款；取消负责停止未来任务和清除本次临时状态，不能撤回已经生效的权威伤害。

5. **为什么既用版本号又用效果句柄？** 版本号防旧调用栈影响新一轮；句柄只移除自己的效果。PredictionKey 另用于预测请求关联，不能拿一个编号代替所有生命周期身份。

6. **两个效果都禁止移动，结束一个会误恢复吗？** 移动入口根据仍存在的限制标签统一计算权限，不让某个效果直接写回“允许移动”。禁锢按独立 GE 管理，眩晕则保留刷新时长策略。

7. **命中准确是否等于实现延迟补偿？** 不是。当前是服务器实时扫掠和几何复核，客户端按轨迹段重建弹体表现；没有服务器查询历史目标位置的命中回溯。

8. **这些优化提高了多少帧率？** 本轮主要减少规则重复、明确职责和治理重入边界，不直接宣称显著性能提升。性能结论需另用固定负载对照，不能拿代码变短当证据。
