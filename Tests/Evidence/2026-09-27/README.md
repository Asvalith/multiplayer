## 性能对照

两条单变量曲线，每组 3 轮，预热至少 5 秒、采样约 30 秒。新增对象均强制网络相关，原地图背景不变。CPU 指标仅为 `Exclusive/GameThread/ServerReplicateActors` 作用域，不是整条 GT。

证据：[performance.json](performance.json)，**42 / 42 通过**，其中 24 轮静止、18 轮运动。42 份服务器 CSV 的指纹均由导出工具核对后生成帧节奏，原始计数不改写。

该正式矩阵使用构建 A，不伪装成最终构建 B 的同一次测量。A→B 仅新增主机超时错误处理保护、对应开发断言和计数说明字符串修正；压力板、门、平台、Transporter 的源码与复制/采样算法未变，Normal 压测也不触发断线分支。具体数值仍归属于 A 的指纹。

构建 B 另外完成 [4 / 4 短压测验收](performance-final-smoke.json)：500 个静止机关的两种休眠设置、20 个平台的两种频率设置，每组一次、预热 2 秒、采样 8 秒。它确认最终程序的负载复制、采样及报告入口仍有效，**不与 42 轮正式数据混算**，不拿单轮短采样重算优化百分比。

### 测量限制

- `GameThreadTime` 原始列全零，视为不可用；不报告 GT 为 0 ms。后续运行器会在展示表中留空，历史原始值不篡改。
- 静止系列实际运行约 44.93～46.21 FPS，运动系列约 44.97～46.00 FPS，60 FPS 只是上限；100/30 Hz 是复制频率上限设置，不是实测每秒发送次数，也不是有画面的渲染帧率。
- B/s 使用引擎发送字节计数（含配置的包头开销），包含背景角色、地图及测试通信，不是网卡抓包、成功送达量或新增机关独占带宽。原测试二进制标签中 `wire packets` 的措辞过强，公开摘录保留原值并附勘误，源码已仅修正该说明字符串，未修改计数或采样算法。

## 本轮查出的真实问题

原地 `World::Listen` 建房没有把监听选项写进引擎 `LastURL`，而 `?Restart` 会重新读取它。旧实现胜利重开后新世界退回单机，客户端无法连回来。现在只在合法的 Listen Server 重开前保留 `listen`，仍然只重载当前关卡，没有自动选图。

首次完整打包回归发现该问题；修复后 Flow 在三档网络中均验证了新世界、目标归零和客户端重新入场。较早的失败日志保留在 `Saved/NetworkValidation/package-flow-normal`，没有改成通过。

进一步核对真实断包日志还发现：引擎会向服务器报告单个客户端超时，旧处理却清除了主机的 Session。原测试只看缓存地址直连成功，漏掉了房间记录。修复后服务端对这类连接错误只记录日志，由引擎移除对应连接；新测试增加 `HostSessionRetained`，核对房间存在、主机身份、广告开关和本轮房间 Token。最终三档网络均通过该断言；它检查会话记录及广告配置，不冒充又执行了一遍完整搜索 UI。

## 如何复现

先构建 Development 包，在项目根目录 PowerShell 执行（把路径替换成自己的游戏二进制路径）：

```powershell
$gameExe = '你的包目录/Windows/multiplayer/Binaries/Win64/multiplayer.exe'
.\Scripts\RunMultiplayerNetworkTests.ps1 -Suite Regression -Scenario All -Profiles Normal,Moderate,Harsh -Repeat 1 -OutageSeconds 12 -TimeoutSeconds 120 -GameExecutablePath $gameExe
.\Scripts\RunMultiplayerNetworkTests.ps1 -Suite Scale -Matrix All -Repeat 3 -WarmupSeconds 5 -SampleSeconds 30 -TimeoutSeconds 120 -GameExecutablePath $gameExe
# 最终构建短验收；不是正式性能对照。
.\Scripts\RunMultiplayerNetworkTests.ps1 -Suite Scale -Matrix All -StaticCounts 500 -MovingCounts 20 -Repeat 1 -WarmupSeconds 2 -SampleSeconds 8 -TimeoutSeconds 120 -GameExecutablePath $gameExe
```

必须使用同一构建和配置比较；先等构建完成再采样，不同时启动多套主机。详细断言和报告字段见 [测试说明](../../README.md)。
